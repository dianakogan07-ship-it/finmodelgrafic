Модель: `09_09_26 - 2026_08_03 ….xlsx` (8,2 МБ, 53 листа, итеративный расчёт: 100 итераций, 0,001).

## Что пришлось поправить (в памяти, файл модели не меняется)

| Проблема | Где | Исправление |
|---|---|---|
| 3D-ссылки по диапазону листов `SUM('1:<'!X23)` → `#VALUE!` | `Summary_> ЖК`, `Summary_> OФ` (~32,5 тыс. формул) | раскрываются в `SUM('1'!X23,'2'!X23,'3'!X23,'<'!X23)` |
| `CELL("ИМЯФАЙЛА";A1)` — русский аргумент, номер очереди из имени листа | `1!C10` … `4!C10` | → `CELL("filename";A1)` |
| `INDIRECT(E195&"!"&…)` — имя листа «1» без кавычек | `Финансирование!…192:237` | добавляются кавычки `'1'!` |
| Критерии `">0,00000001"`, сравнение «Да»/«да» | `DashB_2_*!M12`, `Инвестиции!…` | регион RU + ICU (`CLR_ICU_VERSION_OVERRIDE`) |

## Сверка базового расчёта с Excel

Полный пересчёт книги с кэш-значений Excel: новых ошибок — 0, расхождений > 1e-6 — 25 (шум порядка 5e-6 на листе «1»).
`Dashboard_2!G69` = 18 575 830 371,56 и `E81` = 1,199105 — **совпадают с Excel до последнего знака**.

Время: загрузка + правка формул ~14 с (один раз при старте воркера), пересчёт 2,5–4,5 с.
Откат входов → пересчёт возвращает базовые значения бит в бит. Ужесточение итераций (1000 / 1e-7) результат не меняет.

## Выводы

- Вариант B технически проходит: базовый расчёт 1:1 с Excel, пересчёт ≤ 5 с (критерий ТЗ выполнен).
- Для приёмки нужно заполнить колонки «Excel» по сценариям 1–7 (вписать те же входы в Excel, записать G69/E81) — допуск 0,01 млрд / 0,005.
- Проверить в Excel: при росте цены LLCR немного **падает** (сц. 1, 4, 6). Если Excel покажет то же — это логика модели, а не движка.
- Лицензия: сейчас работает пробная версия Aspose (без ограничений на расчёт в этом прогоне). Для продакшна нужна лицензия Aspose.Cells for Python via .NET; для пилота есть бесплатная временная лицензия на 30 дней.
- Пересчёт однопоточный на книгу: для параллельных пользователей — пул воркеров (каждый держит свою копию книги, ~14 с на старт) и очередь.
